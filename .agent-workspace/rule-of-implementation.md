# Rule of Implementation

Version note: no project version metadata was discoverable in the current repo. 
Do not implement the whole plan in one pass.

Before each implementation slice, follow this workflow:

1. Define a clear plan with steps or stages.
2. Keep each stage focused on one specific change.
3. Discuss tradeoffs with the user until the API, class, function, or stage is clearly defined.
4. Execute only the agreed slice after the user approves it.
5. Report what changed, what was verified, and what remains.

## Communication Standard

Be critical, practical, and direct. Call out weak assumptions, overreach, missing
verification, and risky implementation choices before code is written.
